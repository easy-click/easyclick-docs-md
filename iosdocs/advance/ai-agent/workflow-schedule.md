# 工作流定时任务

定时任务用于在 **AI 智能体** 内，按您设定的时间规则 **自动运行已保存的工作流**，无需每次手动点「运行」。每次触发都会生成一条普通 **任务**，可在 [任务与监控](./tasks) 面板查看进度与结果。


## 打开定时任务页

1. 启动 **新中控**，打开 **AI 智能体**
2. 顶部导航点 **「定时任务」**

页面包含：**新建**、**刷新**、**搜索**，以及当前所有规则的列表。

## 新建一条定时任务

点 **「新建定时任务」**，填写以下内容：

| 字段 | 说明 |
|------|------|
| **任务名称** | 便于识别的名称，如「每日签到」 |
| **工作流** | 选择要自动执行的工作流（支持搜索） |
| **调度类型** | 见下表 |
| **执行次数上限** | `0` 表示不限；达到上限后规则 **自动暂停** |
| **设备忙时** | 见 [设备忙策略](#设备忙策略) |
| **启动参数** | 可选 JSON，会传给工作流（与手动运行时的 params 相同） |
| **目标设备** | **按设备** 或 **按分组** 多选；提交时会解析为具体设备列表 |

### 调度类型

与中控定时任务的 `时间` 含义一致：

| 类型 | 说明 | 示例 |
|------|------|------|
| **每天** | 每天在指定 **时:分:秒** 触发一次 | 每天 9:00:00 |
| **间隔分钟** | 距上次成功触发满 N 分钟后再次触发 | 每 5 分钟 |
| **间隔秒** | 距上次成功触发满 N 秒后再次触发 | 每 30 秒 |

:::info 不补跑

若 AI 智能体进程 **重启或停机**，停机期间 **错过** 的触发点 **不会** 在恢复后一次性补跑。间隔类规则从 **上次运行时间**（或新建/恢复启用时）继续计时；每天类规则只在 **下一次** 匹配时刻触发。

:::

### 设备忙策略

当某台设备 **正在执行其他工作流任务** 时：

| 策略 | 行为 |
|------|------|
| **跳过**（默认） | 该设备 **不参与** 本次触发，其余设备照常执行 |
| **停止当前任务后执行** | 先 **取消** 该设备上正在跑的任务，再启动本次工作流 |

若所有目标设备都被跳过，本次触发失败，列表 **最近错误** 列会记录原因。

### 保存后

- 新规则默认 **运行中**（`active`）
- 列表可看到：名称、工作流、调度说明、设备数、状态、已执行次数、上次运行时间等

## 列表常用操作

| 操作 | 说明 |
|------|------|
| **编辑** | 修改名称、工作流、调度、设备等 |
| **立即执行** | 不等下一次调度，马上触发一次（用于调试） |
| **暂停** | 暂停后不再自动触发，可 **恢复** |
| **删除** | 永久删除该规则 |
| **搜索** | 按任务名、工作流、状态、来源等过滤 |

## 在任务面板里辨认来源

定时触发产生的任务，在 [任务与监控](./tasks) 面板中会标记来源为 **「定时任务」**；若规则有名称，会一并显示（如 `定时任务 · 每日签到`）。

其他来源对照：

| 来源标签 | 含义 |
|----------|------|
| **AI 会话** | 对话安排执行，或对话页工作流卡片点 **运行** |
| **工作流编辑器** | 编辑器内 **试跑** / **运行** |
| **定时任务** | 本文所述自动调度 |
| **手动执行** | 其他 API 触发（少见） |

任务列表 **默认折叠**；点击一行可展开查看各设备执行情况。

## 使用注意

1. **AI 智能体需在运行**  
   定时调度在 AI 智能体进程内执行；进程未启动则不会触发。一般由新中控保活，请勿长期关闭 AI 智能体。

2. **工作流须已存在且可运行**  
   密封工作流（.spk + .spl）需在有效期内；否则触发失败，错误写在定时任务的 **最近错误** 列。

3. **设备与授权**  
   与手动运行相同，需完成 [环境与授权](./prerequisites)（USB 授权、IPA 等）。

4. **并发**  
   同一设备同一时间仍只跑 **一个** 工作流任务；多台设备可并行，受 **设置 → 单任务最大设备数** 限制。

5. **与手动运行一致**  
   定时触发走与 **运行 / 试跑** 相同的执行链，步骤、变量、授权校验行为一致；**不消耗** 对话大模型 Token。

## 常见问题

<details class="ec-faq-item">
<summary><strong>暂停后恢复，会立刻跑一遍吗？</strong></summary>

<div class="ec-faq-body">

**间隔类** 规则在恢复启用时，会以当前时间为基准重新计算间隔，**不会** 因暂停期间积压而连续补跑。  
**每天类** 规则等到下一个匹配的时点再触发。

</div>
</details>

<details class="ec-faq-item">
<summary><strong>改了分组里的设备，定时任务会自动跟吗？</strong></summary>

<div class="ec-faq-body">

创建时若选 **按分组**，保存的是当时解析出的 **设备 ID 列表**。分组后续增删设备 **不会** 自动同步到已有规则；需 **编辑** 定时任务重新选择，或改用 **按设备** 指定。

</div>
</details>

<details class="ec-faq-item">
<summary><strong>执行次数到了上限会怎样？</strong></summary>

<div class="ec-faq-body">

规则会自动变为 **已暂停**。可在列表点 **恢复** 继续（若仍达上限需先 **编辑** 提高上限或清零逻辑——当前以 `execCount` 累计为准，编辑不会自动重置次数，需新建规则或后续版本支持重置）。

</div>
</details>
